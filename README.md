# 嘎嘎小狗总结

SillyTavern 1.18.0+ 的剧情记忆扩展。它把过长聊天压缩为有文笔的前情、结构化状态和场景记忆，在保存并校验成功后自动将已覆盖的旧消息退出模型上下文；原消息不会被删除，可以恢复。

## 当前版本

- v0.1.16 手动“立即总结”不再受 60000 Token 自动触发阈值截断：它会锁定除保留近期消息外的全部旧正文，在后台按安全大小连续分批，直至完整范围全部完成；“继续”只在主动中断或生成失败后出现。手动与自动模式统一使用界面中的保留消息数。悬浮小狗支持鼠标和触屏拖动、边界限制及位置记忆。设置开关改为小尺寸前置对齐，两列组成居中的紧凑设置区。
- v0.1.15 缩小设置区滑动开关，并让开关紧跟对应条目文字；左右两列之间改用更宽的独立列间距，减少单个条目内部的空洞感。
- v0.1.14 拆分面板与悬浮按钮图片：面板标题继续使用第一张小狗图，右下角悬浮按钮单独使用透明底白色小狗爱心 PNG；悬浮按钮移除粉色圆底、边框与圆形裁剪，直接显示透明图片。
- v0.1.13 将设置区灰色方形勾选框改为粉色滑动开关，并以插件专用高优先级样式隔离酒馆主题覆盖；标签在左、开关在右，桌面和手机布局一致。
- v0.1.12 将标题、悬浮按钮和设置入口的旧小狗图标替换为新的透明底白色小狗爱心图；图片通过模块路径加载并在小尺寸下裁剪显示。
- v0.1.10 提高设置区复选框的可见度：未选中状态使用清晰边框，选中状态显示高对比粉色底和白色勾选，不再依赖酒馆主题的淡灰原生样式。
- v0.1.8 改用酒馆原生 `/hide 起点-终点` / `/unhide 起点-终点` 路径隐藏和恢复消息；这会同步酒馆消息对象、聊天气泡和聊天保存，而不是只给消息加插件标记。若旧版酒馆没有暴露该命令，才回退到 `is_system` 兼容模式。
- v0.1.7 修复检查点已存在但文学前情未回填时的假成功状态：面板会优先从最新已提交检查点恢复前情；检查点和前情都缺失时会明确提示重建。
- v0.1.6 将自动总结的默认批次提高到约 60000 Token，并按消息边界分批处理积压正文；一批成功后会继续检查下一批，不会把全部历史一次性塞进同一个请求。仍使用旧版默认 1800 的设置会自动迁移到 60000，用户自定义的其他数值保持不变。文学前情新增独立润色阶段：先写忠实草稿，再以结构化事实为边界润色正式版本。
- v0.1.5 改用 SillyTavern 标准 `chatMetadata` / `saveMetadata()` 保存每个聊天的总结状态，并自动迁移旧版字段。模型只返回散文、空 JSON 或保存失败时，不再显示“已就绪”，也不会隐藏旧正文。
- 使用 SillyTavern 当前连接和模型，不需要额外 API Key。
- 总结优先复用 SillyTavern 当前主聊天的 Chat Completion / Text Completion 服务与 `normal` 参数构造链，直接接收 SSE 流；只有当前 API 类型未暴露扩展流式服务时才回退 Quiet/Raw。
- 事实提取、前情草稿和文学润色均支持实时流式显示、立即中断和继续；中断任务保存在当前聊天元数据中，完成前不会隐藏原消息。
- 三个生成阶段彼此分离；正式文学版会参考正文样本，同时不得越过结构化事实边界。
- 保存场景卡、事实、当前状态、关系、未结事项和检查点。
- 通过消息哈希检测编辑、删除和 Swipe，使受影响的检查点失效。
- 自动隐藏由插件处理的旧消息，并支持一键恢复。
- 通过扩展提示词把记忆发送到正常回复请求中；注入内容可预览。
- 关键词召回已内置，向量召回暂未作为首版依赖。
- 提供安全注入（只发事实）和平衡注入（事实与文学前情）两种模式。

## 安装

把整个 `gaga-dog-summary` 目录放到：

```text
SillyTavern/data/<你的用户>/extensions/gaga-dog-summary/
```

刷新页面，在扩展设置中点击“打开嘎嘎小狗总结”，或使用右下角的悬浮按钮。

## 使用建议

1. 第一次使用先点击“立即总结”，确认前情和注入预览。
2. 自动模式默认在可总结旧正文积累约 60000 Token 后启动，并保留最近 10 条消息作为原始正文和文风锚点；手动点击“立即总结”不等待阈值，会一次处理完整旧正文范围。
3. 默认在成功保存后自动调用酒馆 `/hide` 隐藏已覆盖的旧正文；“恢复隐藏”会调用 `/unhide`，不会删除消息。
4. 发现编辑或 Swipe 后出现橙色失效提示时，等待自动重建或点击“恢复并重建”。
5. 如果担心总结文字影响主模型文风，可选择“安全：只发事实”；如果希望模型获得更连贯的叙事前情，可选择“平衡：事实与前情”。

一次总结只有同时满足以下三项才算成功：状态栏显示“已保存检查点”，检查点数量至少为 1，并且“文学版前情”出现内容。“生成进度 / 原始返回”会依次显示事实结构、前情草稿和文学润色的当前阶段；最后停留在润色稿时，它可能与已保存的文学版相同，但原始返回本身仍不代表已经保存。

## 流式生成、停止与继续

v0.1.3 起采用与“嘎嘎世界锻造”和“嘎嘎人设生成器”相同的酒馆接口适配：Chat Completion 使用主聊天的 `normal` 参数构造器，Text Completion 使用当前预设生成 payload，并由酒馆对应服务发送流式请求。插件不再把 `generateRaw()` 或 Quiet 作为首选通道。

生成进度框会实时显示模型已返回的内容。手动总结遇到十几万 Token 时，插件会在后台自动衔接多个安全批次，用户只需点击一次“立即总结”。点击“中断”后，插件会终止当前请求，保留完整目标范围、当前批次、已完成阶段和当前输出；点击“继续”会先恢复中断阶段，再自动完成剩余批次。只有批次完成生成、解析并保存成功后，对应旧正文才会退出上下文。

启用正式文学润色后，每批总结会产生三次后台模型请求：事实提取、前情草稿、文学润色。第三次请求只负责改善语言与结构，结构化事实是不可改变的边界。

如果上游代理缓冲 SSE，生成仍可完成，但可能只在最后一次性出现完整内容。面板会显示有效分片数量，便于区分真正流式和上游缓冲。

## API 兼容说明

若直接流式通道不受当前 API 类型支持，插件会依次尝试 Quiet 和 Raw 兼容通道，并在错误中显示实际 API 来源及详细响应。酒馆正常聊天可用但插件仍出现 502 时，请保留完整错误文本，以便判断是 Chat Completion 参数构造、反向代理还是模型端拒绝。

设置页入口使用 SillyTavern 标准扩展抽屉，并针对手机窄侧栏强制横向排版；按钮空间不足时会省略文字，不会再逐字竖排。

## 消息范围与酒馆索引

酒馆消息索引从 `0` 开始，范围两端都包含。插件内部保存的“消息 `0–89`”会对应酒馆的 `/hide 0-89`，不是按人类口语楼层重新换算。设置“保留近期消息 10”时，手动与自动总结都会保护最后 10 条，只处理此前的旧正文；如果一次模型请求装不下完整范围，插件会自动建立多批检查点并逐段隐藏，不要求用户手动点击“继续”。

## 数据安全

- 总结请求会把待总结正文发送给当前配置的模型服务。
- 正常聊天时，已自动隐藏的旧正文不会再次发送；发送的是压缩后的记忆。
- 插件不删除聊天消息，不上传到额外服务器。
- 用户原本手动隐藏的消息不会被插件自动恢复。
